# 真实调用与恢复机制修正：2026-10-02

当前引擎 `workspace-agent-2026-10-02.15`；**尚未通过真实公司数值估值到报告的生产验收**。没有公司专用取数模板，没有注入答案、改写主体或用零填缺失值。下文早期结果为历史记录，后续改动与验证单独列出。

## 实测发现与修正

- 可比公司的原文数值可读，但模型会遗漏 `role=comparable`，甚至沿用目标公司的主体。文件阶段现在要求 LLM 明确主体代码和角色，执行器拒绝后续越界；提取错误区分角色/主体问题与金额定位问题，不再对所有错误都提示“重新定位金额”。事实仍须依据原文复核，不因进入文件阶段就视为正确。
- 32K 上下文下，元数据、工具说明与旧对话占用空间，供应商拒绝请求后原有程序只删工具历史，仍可能因为基础状态太大而停止。现在优先压缩可检索元数据和旧助手叙述、为最新工具反馈保留空间；不删除系统要求、任务、用户消息和约束。压缩后的错误结果仍保留失败原因，避免模型看不到错误又重复调用。
- 文件检索原先只按已缓存块的插入顺序返回匹配，短词可能淹没具体词；先扫描后半部还会影响所谓的原文顺序。现在使用不含金融规则的词频相关性排序，并支持明确的原文页序和 any/all 匹配；不根据关键词推断数值含义。
- 同模型开启思考后，连续三次用完 6000 输出 token，均未生成任何工具内容。新增 `LLM_REASONING_LIMIT` 分类，此情形不再按 JSON 语法错误原样重试；不擅自切换思考模式、提高预算或更换模型。
- 新会话独立抽查发现：2025年末股数单元格还被用作2023年末，复核文字指出期间不支持，但结构化六项检查仍全部为 supported。不能依靠此模型的自我检查作为验收。新增原文数值位置的跨期冲突检查，并在正式估值交接再次检查，不能由复核按钮消除。对原始失败数据库只读回放，新检查捕获两条冲突引用并阻断交接，没有回写测试历史来美化成绩。
- 文件任务中的主体/角色常量约束来自 LLM 自己的显式声明，不由代码猜公司或补字段值。同时修正 C 级可比基础字段无法参加交叉核对的遗漏；市值、年度利润和收入可核对，直接 FY 倍数的交叉核对同时区分分母年度。来源等级不会升级。
- 每轮开始即检查历史观察的跨期位置冲突，降级后让主模型看到真实修复任务；不等到计算才暴露问题，不修改冻结的旧运行。
- 复核只暴露当前包的真实ID，先说明依据再给判断；整批预检防止后项参数错误留下前项部分确认，同批重复事实不能相互覆盖。这不是对自然语言理由正确性的自动证明。
- 真实续测又暴露“年报中的股数被写为annual”的模型类型错误。原先成功保存后的统一提示仍要求继续复核，会浪费调用。逐行next_action优先修正模型解释，不切换阅读器；早期曾将聚焦全存量字段的schema锁定instant，后续发现会诱使模型把其他科目也写成存量，`.10`已删除该限制，计算器仍检查每项真实字段类型。
- 增加只读原文审计：编码助手查看原始PDF第7、55页图，独立记录三年利润和两期股数，与提取模型的记录比较。`.7`模型改从第36页的分红说明取得年末股数，随后单独渲染该页核对，加入允许定位范围，原有预期数值不变。它不是人工审计或多行业金标准，案例不进入Agent上下文。真实验收脚本新增非零失败退出码和数值报告/复算门槛，不再以程序正常退出冒充成功。

## `.15` 从零事实开始的取证目标

工作计划此前只有在已有confirmed股数时才暴露120天时效要求；没有股数或只有待修复旧股数时，模型反复修旧年报。现在即使零事实，也显式呈现目标年度和当前股数日期窗口；过旧股数修复仍保留在审计清单，但不作为当前优先动作，不删除候选、不放宽准入。目标年度不是已披露断言，不允许使用截止日后资料。
