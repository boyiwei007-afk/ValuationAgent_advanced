# 文件工作区：读取、理解与交付

引擎 `workspace-agent-2026-10-07.80`。这是生产化能力建设，不是已完成多租户公网部署认证或任意公司估值验收；当前实测边界见 `DEPLOYMENT_READINESS.md`。

统一输入常规阅读与证据详情分开：`inspect_inputs`保留数值、单位、日期、来源类型及限制，不在每行重复完整证据；`include_evidence=true`恢复原文引文与定位哈希，审计存储不裁剪。分页使用返回的`next_action`；`evidence_action`只查看当前页对应输入的证据。已有输入且本轮有编辑权限时，声明计算工具持续可用，不强制重新提取或加载。

已复核文件中的可比EBITDA和资本科目可以进入统一输入，不再仅限收入、净利润、市值。原始金额仍可as_raw保存，再通过带entity_ticker的同主体公式解释；不降低来源或期间检查。报告v14展示可比EV桥接的余额日、行情日、带符号调整及未建立项目。`.77`真实公司测试完成了供应商输入到PE/PS计算和报告，但仍未完成EV/EBITDA，文件提取工具未被调用；不能称为真实LLM文档理解已稳定通过。

读取工具schema只展示当前文件类型可用的视图。可信供应商JSON可用`view=records`直接展开，程序提供实际路径和列映射；其他JSON仅在完整检查下存在唯一对象数组时默认选择，歧义仍需显式路径。成功读取提供下一步工具定义，不强制执行或自动批准事实。供应商契约已经绑定的raw.*输入直接按ID做口径解释，不重新转抄为文档事实；上传PDF/Excel仍由LLM理解来源内容。

用户原话读取不是固定财务模板。关键词按空格、竖线、顿号、逗号、分号或换行拆分并作字面OR匹配，不执行正则；返回真实行号和数值引用，不自动判定字段。单页最多30行，更大limit按服务器上限分页；未命中给出无关键词续读参数，不把检索表达式不匹配解释为数据缺失。正式计算默认保存同run_id审计报告；用户要求仅对话展示时尊重artifacts禁令，仍保留内部计算审计，不生成可下载文件。

文件阶段误调用当前目录以外工具时，允许每个文件/角色一次返回主循环重新决策，原始阅读和已保存事实不丢失。被拒绝调用本身不执行，也不绕过权限。来源定位以保存的page/sheet/cell为准，block_id后缀只是块标识；最新实测仍发现LLM把块编号写成页码的正文问题，尚未认定追溯展示全面通过。

LLM不再必须把每个原始金额挤进最终模型字段。`extract_observations`可用`raw.`前缀保存已解释的原始金额；原文绑定和语义复核通过后，以`record_inputs(source_values=[{fact_id, as_raw:true}])`选择。`record_inputs(calculations=...)`再引用真实`input_id`声明EBIT、现金／债务或经营营运资本的加减、理由和风险；不接收代码、数值常量或手算结果。完整年度流量与时点存量分别校验，报告将建模判断与原始披露分开。当前只支持这些明确的加减构造，不是任意公式执行器或金融分部模型。

经营营运资本余额可包含LLM已说明的合同项目、票据等，不局限于三项模板，允许负数。连续完整年度同口径余额在变动额缺失时可由程序求差，保留两个年度的依赖；不要求为了这一字段再强制检索现金流表。余额差与现金流表调整额不混称，已有变动额不被覆盖，缺失首年和跨年断档不填零。报告v10展示期初日期、公式版本及并购／汇率／重分类限制；离线复算重新执行该检查。

更正原始输入后必须显式替换依赖旧ID的公式，不自动套用新值。既有来源输入缺少新版期间类型／原始标签时，需按原始文件重新选择并用`replaces`替换旧记录；不为兼容旧数据伪造新元数据。冻结结果不因此被改写，离线复算需要对应的计算源码版本。

统一输入工作状态不再展示全部记录和原始API证明。`inspect_inputs`可分页读取已保存的数值、来源、可比选择、取数覆盖和缺口，不触发联网或重新解析。用户直接给出的数值由`amount_text`定位原消息，不要求LLM重写引文；完整数值、单位、日期和来源性质的校验仍保留。这与PDF文件的读取／语义解释是不同入口，不强迫自然语言用户输入先走文档取证。

JSON 文件（用户上传与 API 快照均适用）可先 `inspect_file` 查看数组路径和真实字段，再以 `read_file(view=records, record_path=..., record_filters=..., record_fields=...)` 读取所需记录。筛选不修改原始响应，保留十进制精度、空值和 JSON Pointer；不逐条翻完全部供应商记录，不把读取恢复当成再次下载。

嵌套列式 JSON 可指定 `record_path="/data/items"` 和 `record_columns_path="/data/fields"`，由程序按原始列位置形成阅读视图。不猜列名、不截断多余单元格、不补缺失值；列名重复或行宽不符时报错。返回行 Pointer 和逐字段 column_pointers，分页保持同一筛选条件。目录最多探索4层、20个数组，预览有界；不是全文件无损结构索引。

字段名错误返回当前真实列名，引导重新查看目录、用records读取一行并核对原始日期格式，不把结构错误误判为原文缺失或推荐整份单行JSON。专注文件阅读也参与有界上下文压缩，保留用户约束和可检索证据ID；复核包超限时不得删除原始证据来强行让复核通过。

Tushare 的保存文件为原始 HTTP 响应内容，十进制数读取时保留字面精度；中文标签视图属于有接口说明链接的供应商字段投影，不冒充发行人文字披露。行情日期与财报发布日期分开；原始 JSON 中未通过日期筛选的记录仍可能被阅读，字段提取和模型准入必须继续执行信息截止日校验。

涉及公司数据的 `write_research_note` 必须引用实际读取的原文块；仅概念性说明可明确选择 `basis=concept_note`。笔记不是原始来源，不能回灌为已核验事实。已复核的标准字段通过 `record_inputs(source_values=...)` 进入模型工作区，可与用户显式假设合用。API 已注册字段由 `fetch_financial_history` 展示带原值及期间的分页候选，`provider_values` 只选择 `candidate_id`，程序重读原始文件与记录，不要求模型再次转抄字段映射。用 `list_input_candidates` 筛选年度/行情日并分页；缓存读取也验证原始哈希。其他字段仍须解释和复核。源码中的旧科目推导和取证组装仍待迁移删除。

开源实现调研：已核对 [Docling](https://github.com/docling-project/docling) 的布局、表格、OCR与统一文档表示能力，以及 [pdfplumber](https://github.com/jsvine/pdfplumber) 的字形坐标/表格读取和 [openpyxl](https://openpyxl.readthedocs.io/en/stable/tutorial.html) 的工作簿读取。当前仍使用项目已有解码器，未安装或声称完成 Docling 接入。新增解码器必须提供原文位置和失败诊断，不能替代 LLM 财务语义判断；Excel 公式与缓存值也不能冒充重新计算结果。

单文件任务的 `metrics` 是阅读重点，不限制只能输出这些字段，不能把利润强迫映射成股数。主体/角色/文件范围仍受约束；行业文章或尚未识别主体时可用 `role=reference` 只读探索，识别后返回主循环，再按真实公司提取。

来源元数据缺少发布日期时，LLM可通过 `basis.source_published_at`、`source_publication_refs` 引用当前文件原文。日期主张和引用纳入证明哈希，复核须单独填写 `publication`；原有元数据冲突不能覆盖，未知/未来日期不放行，C级来源仍需交叉核对。不会从报告期、批准日、抓取日或父目录自动推断披露日。

非PDF不能用 `page` 过滤正文；明确报参数问题，不再静默返回无文本。超出块内行数的空窗口单独报 `READ_WINDOW_EMPTY`；恢复建议仅附当前来源，完整历史可用进度工具查询。

## 开源组件的采用边界

当前PDF表格视图实际使用[pdfplumber](https://github.com/jsvine/pdfplumber)保留文本、网格和坐标；它更适合有文本层的PDF，不能当作扫描件OCR。复杂版面与扫描件参考[Docling](https://github.com/docling-project/docling)的布局、表格和OCR管线，但尚未集成其运行时。搜索后网页正文的获取参考[Crawl4AI](https://github.com/unclecode/crawl4ai)，尚未替换当前下载器或加入浏览器渲染。通用文件转阅读文本也可参考[MarkItDown](https://github.com/microsoft/markitdown)，但Markdown不能取代财务证据需要的PDF坐标、Excel单元格和公式／缓存值区别。

采用这些组件的共同原则是：解码器保留可定位结构，LLM理解财务含义，程序处理可证明的数值换算和计算。来源按需读取，不整份灌入上下文；解析失败先区分下载错误、无文本层、布局歧义与模型输入缺口，再选择恢复方法。不能仅更换解析库、关闭来源检查，或把第三方宣传的支持格式当作本系统验收结果。

`.36`支持已复核原始科目进入统一工作区，再按注册公式推导模型输入；无需把原始科目重命名或要求LLM重复抄写计算结果。推导只使用同年同口径依赖，缺失不补零；报告v8显示公式及依赖来源。尚未迁移的经营利润调整、债务／现金桥接等旧逻辑仍须审查，不能称为全部通用会计语义已实现。

## 统一处理路径

1. 上传与检索下载保存相同的原始文件记录：文件ID、SHA-256、字节数、取得方式、来源等级。搜索摘要仍只是线索。
2. `list_files` 列举本工作区资料；`inspect_file` 返回PDF页数/书签目录、工作表名称和支持的视图。新PDF初始只读前25页，由模型决定再读哪些页；初始解码失败仍保留下载文件，换视图不用再次下载。
3. LLM 自主选择 `read_file` 的文本检索、原始文本行、PDF坐标/布局/阅读顺序、XLSX矩形区域；这些工具只解码和保留位置，不按公司或固定年报模板解释财务语义。`pdf_geometry` 使用 pdfplumber 字符坐标恢复空格，记录解码库版本和容差；不推断金额、年度或缺失值。纯扫描件没有文本字符时不会凭空产生文字。
4. 每份原文在打开前检查工作区归属、存储路径和哈希。新增文本视图只追加并复用引用块，不覆盖原文。引用页码来自位置而不是块ID后缀。
5. 文本质量不足时，配置允许的主模型可通过 `view_pdf_page` 查看页图。局部图片只发给下一次模型调用，随后移除大图、保留位置与哈希。日志不记录base64图片。
6. LLM 使用 `extract_observations` 解释主体、期间、单位/币种、口径和经济角色，并引用原文片段；不再依靠旧表头契约判定语义。程序只核验原文位置、数值完整性、确定性换算和模型约束。随后 `prepare_observation_review` 返回原始上下文及绑定任务/来源的复核包，`review_observations` 记录逐维判断。原文定位、LLM复核、模型准入是不同状态，不能用置信分替代证据或复核。
7. 生成文件后回读检查内容，再交付用户。CLI与Web共用工具、存储与报告服务。

## 解释与复核协议

- `begin_file_task` 让同一主模型集中处理指定文件和至多6个目标字段，并声明实际 `entity_ticker` 与 `role`，完成后 `end_file_task` 返回主对话。历史数据只属于目标公司，可比企业须明确另一主体；字段角色不一致时执行器拒绝，不自动改写为目标主体。局部最多16步（待复核收尾有一次宽限），不增加总调用/时间预算。当前文件的错误候选可显式撤回，已确认事实不能借此撤回以绕过校验。当前阶段只在本轮运行时有效，重新开始仍读取已保存事实。
- `read_file(block_id=...)` 直接读取已有原文块；显式设置 `start_line/line_count` 时返回原始行号、总行数和续读位置。块ID后缀不代表PDF页码，窗口化不改写已保存原文。
- `search_file` 默认按查询词的通用稀有度和覆盖排序，避免“股”等短词淹没具体匹配。`order=document` 可恢复实际页序，先扫描后半部不会改变该顺序；`match_mode=all` 要求同一行命中所有查询词。相关性不代表财务正确或来源权威，模型仍须打开原文解释。
- 文件阶段会将 LLM 已明确声明的文件、主体、角色和字段范围写入本阶段工具 schema，避免默认历史角色覆盖可比角色；不从公司名称猜测角色，不替模型改写提交内容。全存量字段的聚焦任务使用instant类型，具体日期仍须原文。原生协议仍有执行器的同等检查。
- 同一原文数值位置被同主体、同字段同时赋给不同期间时标记 `SOURCE_PERIOD_COLLISION`，复核和估值交接均拒绝放行。模型须撤回错误项、用 `replaces` 显式更正或取得独立期间证据；同一数字确实同时适用多期的特殊文字披露目前也需补充独立依据。此检查不等于能判断全部年份含义，也不覆盖所有跨视图错配。
- 每轮启动时先检查已存储观察的跨期位置冲突，将历史误确认项降级为proposed并记录审计事件，再交给LLM修正；页面读取不隐式修改事实，旧估值冻结快照保持原样。
- 提取/复核逐行返回 `next_action`，`MODEL_*` 类型错误先用replaces更正，不再一律提示复核。复核工具参数限于本次包的实际ID，批次预检失败不部分确认前面的记录；格式约束不能证明语义正确。

- 每批至多12个观察、64个命名片段。片段为当前文件内的原始块ID及1起始行号；`quote` 可省略，由程序取回所选原始行，不要求模型重抄空格。显式填写时仍必须是连续逐字引文，重复引文使用0起始的 `occurrence`。`value_ref` 和各类 `*_refs` 引用命名片段的键，不能填入金额或整段文字。单位注释可以出现在数据后面，跨页依据和各行不同口径由LLM解释。
- `basis` 包含主体、口径、计量单位和币种，各自引用原文；`row.basis` 可覆盖共享解释。币种不明或非CNY金额不会悄悄换成人民币入模。
- 金额片段可以是整行或多行：LLM 选择 `raw_value`，程序在引用范围内核验与之等值的完整数值并保存 `resolved_value` 精确字符位置；不会自行决定数值属于哪一年。同值多次出现时须用0起始的 `value_occurrence` 指定或缩小引用。不能丢负号、括号、百分号或截断相邻数字。PDF粘连列优先换 `pdf_geometry` 视图；上下文充分时LLM可用 `value_segments` 显式声明整串分段，程序检查连续、无遗漏、无重叠，LLM复核分列/年度依据，不由正则猜列。分段字符完整不证明语义正确，仍有歧义必须保留待补证。横线/空白不自动当零。
- annual仅完整日历年度，instant为明确时点；interim/ttm不会混入年度序列。重述列必须有重述证据，股数不能由股本面值代替。
- 复核包检查文件/块哈希、原文位置、保存的解释和当前研究任务；改变来源、模型处理或证据后不能复用旧包。单项上下文最多24000字符，单次复核包总量最多48000字符。同批相同块只在顶层 `original_context` 返回一次，每项通过 `context_ids` 引用；不会把共享上下文计作多个独立来源。
- 营业收入、归母净利润、税前利润、所得税费用及股数等直接披露科目，不因未单独指定经营/融资角色而被一概阻断；仍需完整证据和语义复核。现金、债务、利息、FCFF和金融子公司桥接等依赖会计处理的字段保留角色约束，不以“更宽松”为由放行未知处理。
- `replaces` 保存更正链，只在新观察通过准入后撤回旧项。一般更正限同主体、标准科目、期间和口径；若修正原解释的年度/单位/口径/科目名称/映射，须保持同一主体和完全相同的原文数值位置及块哈希，不能撤销其他单元格或无关事实。未解决冲突不能靠平均或挑选来源消除。
- C级来源即使复核支持仍需跨源一致性核对。相同快照、同站子域不能充数；不同可比公司不能互相佐证。来源等级不会因此升级。
- 同一个主LLM既提取又复核，存在相关错误风险；这是显式检查阶段，不是独立审计或人工批准。
- `reading_attempts` 有界保存最近128次尝试；恢复工具提供换视图、修正片段、定向替代来源等选择，由主LLM决策，不自动增加网络权限或重置预算。
- 恢复尝试关联失败事实，跨文件批次分别归属原件。已更正/撤回的失败解释保留审计，但不继续推荐修复；无法关联到事实的定位失败仍保留。`saved_count`只计新观察，重复记录另报`duplicate_count`，重复提取/复核不重置读取进度计数。
- 错误返回选中原文、有效锚点名称及可能的金额位置，交由LLM修正；位置候选不会自动保存事实。连续读取但未落地字段时只给进度建议，不阻止必要阅读。单次模型回复支持最多6项工具调用，先校验再逐个执行，所有结果返回模型后再决策；仍受总时间、轮次及无进展限制。

## 文件交付

JSON 记录读取的模型参数明确区分于 PDF/文本读取：必须提供 `view=records` 与实际数组 `record_path`，列式响应另填列名数组路径，不混用 PDF 页码或工作表名。字段筛选无匹配时返回有界原始筛选值示例，不自行转换日期、把空结果填零或重新下载。省略视图但明确传记录选择参数的直接调用可进入 records；数组路径仍须明确。模型负责选择真实记录，工具保留原始 JSON Pointer。

- `search_file`补齐文件探索入口：PDF默认扫描最多300页（可指定最多600页），不受最初25页缓存限制；返回有界原文摘要、全文命中页索引、后续页/命中游标、空白或解码失败页。原件哈希先核对，索引缓存保留原文块，不创建财务事实。单次索引最多150万字符/2000块，仍受每文件5000块上限和原执行时间预算约束。非PDF只查已存文本并明确披露不是全文覆盖；跨行词、扫描件仍可能漏检。
- `analyze_sensitivity`保存独立JSON情景报告，含冻结基准输入和数值结果。支持DCF的WACC/永续增长、相对估值倍数或分母倍率及股数倍率；不改原模型，不把试算假设作为新事实。Web文件卡标记“敏感性分析 · 假设试算”。

- `write_workspace_report`：系统结果/缺口报告，支持Markdown、PDF、HTML、JSON。状态与数值取自现有证据和确定性计算，不接受LLM自行指定“计算完成”。
- 尚无数值结果的估值任务在执行失败或检查点停止时，终态保存Markdown中断报告：`kind=interruption_report`、`numeric_result_available=false`。受原有文件配额/哈希保护，同请求幂等；纯聊天失败、用户取消不自动生成估值文件。它不是数值报告，不表示穷尽资料或后台续做。
- `write_research_note`：LLM自由撰写的Markdown笔记，醒目标为未审阅；引用必须存在于当前工作区。不会注册为来源或自动变成财务事实。
- `list_artifacts` / `read_artifact`：列举、回读生成文件。文件和元数据以SQLite事务保存；下载前校验哈希。相同报告版本、相同格式复用已保存字节，不覆盖旧版。
- 生成文件的“版本”只是交付记录，不是恢复旧Agent流程。清单含输入修订、报告ID、状态、计算run ID及文件哈希。
- `/export` 和 `/save` 在本地创建文件及manifest；同名不同内容拒绝覆盖。Web文件卡下载经过工作区归属检查的文件，不直接暴露服务器路径。
- `GET /api/workspaces/{id}/files`、`.../files/{file_id}`、`.../files/{file_id}/pages/{page}` 提供清单、结构和页图；`.../artifacts` 与 `.../artifacts/{artifact_id}` 提供输出清单/下载。

## 视觉能力与配置

PDF除文本视图外，可用 `read_file(view="pdf_tables", page=真实页码)` 调用pdfplumber表格检测。返回本页表格目录、逐行原文、`cell_details` 中的单元格文本/地址/边界框，以及解码器版本。`table_index`选择表，`offset/limit`翻行；无框表可显式选择`table_strategy="text"`，不会自动把两套布局混成一份原文。引用仍使用保存的block_id/行号，金额不得由空格或合并占位推成零。

检测网格可能因底色矩形等产生额外行列；它不是会计科目识别，也不是OCR。`no_tables`仅表示当前策略未找到表格。表外标题、币种/单位和附注须补读同页文本或页图；空白格与未单独检测到的合并格分别记录，不继承相邻金额。每页最多50个表、所选表最多5000格，并受通用文本视图和文件块限额约束。

可选安装 `python -m pip install -e ".[vision]"`。PDFium按单页渲染，最长边不超过1800像素，原始PDF不变；工具审计记录原文哈希、图片哈希、渲染器版本和缩放比例。

CLI `/vision` 明确启用，或Web模型连接勾选图片选项。环境配置使用 `VALUATION_LLM_SUPPORTS_IMAGES=true`。这只是用户对接口能力的声明，不是视觉质量认证；连接测试不发送图片。没有视觉能力时返回明确错误，不能假装看过页面。不同模型计费/支持格式不同，由用户配置提供方决定。

视觉识别帮助主模型理解布局、对照文本层；目前不会仅凭视觉读数绕过原文绑定。纯扫描件无可交叉核验文本时仍需OCR/人工复核或其他可追溯来源。这是尚未闭合的能力，不应宣称扫描件自动财务入模已生产可用。

## 限额与安全

- 原文50 MB；Office解压150 MB/10000条目；单次新文本视图40000字符/200块；每文件累计5000视图块。
- XLSX每次最多400格、行号≤10000、列号≤1024。保留空值、公式及缓存，不执行宏、外链、工作簿公式。缓存可能过期，不能声称已重算。
- PDF精读每次一页，全文定位扫描单独遵循索引限额；每轮最多8张模型页图；单张PNG≤6 MB。图片使用主循环原有时间和调用预算，不另开不受控模型循环。
- PDF显式传page且省略view时读取该页坐标视图；显式text+page只检索该页缓存，不能忽略页码。默认每次返回3块。模型上下文去掉相同正文/编号行的重复副本，完整审计不变；搜索长摘要只传有标记的预览，保留所有来源ID、URL和日期。
- 指定页面/单元格视图时query不丢弃未匹配原文。纯文本检索未匹配返回`no_match`，与无文本层的`no_text`区分，不能误诊为扫描件。超长批量结果优先保留仍可容纳的完整正文，省略部分带可检索的文件/页码/字段指针，不再整批抹掉来源位置。
- 上下文超限最多压缩重试2次，保留任务约束；工具JSON截断/协议错误最多重新生成2次，失败输出整条不执行，不重放先前成功的工具。相同状态下重复更新任务/计划也有保护，避免成功空转耗完预算。
- 单个生成文件10 MB；单工作区最多100个/50 MB。写入事务中检查配额；断电不会只保存一半BLOB。宿主机磁盘总量仍需部署层监控。
- 文档/网页/生成笔记均视为数据，不能修改权限、偷取密钥或执行命令。HTML报告按附件返回并设置nosniff/sandbox；自由笔记只输出Markdown。
- 不提供任意宿主机路径读写或Python/shell执行。若未来支持临时脚本，必须使用独立容器/进程权限和网络白名单，不能把普通subprocess称为安全沙箱。

## 尚需生产部署验收

当前默认只监听127.0.0.1。工作区归属校验不是用户身份认证；不能直接作为多用户公网服务。上线前仍需要身份/租户隔离、上传扫描、反向代理限流、备份恢复演练及监控。

文件库当前在服务进程内运行，限额与取消检查是应用层约束，不是操作系统级CPU/内存隔离；畸形文档可能卡住底层库。生产的不可信上传必须迁到受限解析worker，配置硬超时与进程回收。还需补Excel合并区域/隐藏行列的完整布局视图、独立视觉转录复核、不同PDF的真实评测集。

确定性计算可用既有离线复算包验证；LLM读取/解释输出不保证重复生成逐字相同。已保存原文、报告字节与哈希可精确复核，不能把这两种复现能力混为一谈。没有真实模型、多行业端到端验收前，不声称所有公司可一次自动估值成功。
