# 金融插件接入契约

## 边界

Web 和 CLI 共用 WorkspaceAgentRuntime。模型负责计划、取证和解释；ValuationRunner 只执行确定性金融计算，不接收 LLM、不提供结果聊天或第二次模型审核。

默认金融实现为 FinanceTeamModel。ReferenceFinancialModel 仍用于显式合成 demo 与金融单元测试，不是缺少行业、资料或模型连接时的降级方案。

## 输入

ValuationRequest 是冻结计算请求，不是网页或命令行向导状态。

| 字段 | 含义 |
| --- | --- |
| company / valuation_date | 计算主体、币种与估值日 |
| language | zh-CN 或 en-US；语言不能改变财务数字 |
| mode | snapshot 或显式 demo；已移除 live 模式 |
| data_source | structured、ticker 或 upload |
| financials / historical_financials / peers | 财务快照、历史序列和可比公司 |
| assumptions / assumption_evidence | 明示假设及其依据 |
| methods | dcf、pe、ps、ev_ebitda |
| forecast_years / discount_policy | 显性期长度与折现政策；正式引擎检查适用条件 |

Decimal 通过字符串进行 JSON 序列化。EvidenceRef 保存来源、原文位置、时点及字段路径。不得用搜索摘要、默认零值或模型推断填补缺失历史财务。

DataProvider.resolve(request, store) 返回 DataBundle。资料解析、事实核验与假设提案由工作区完成；确认标识 confirmed 表示机器核验，不自动代表人工批准。

## 插件与计算

FinancialModelPlugin 的实际协议以 `src/valuationagent/core/plugins.py` 为准。输入校验、假设、预测、DCF、相对估值、敏感性和结果比较均返回类型化数据。新增实现必须声明版本、适用范围与字段要求，不能靠异常时切回旧算法通过验收。

工作区在执行前冻结 ModelSpec、来源快照及证据使用记录。参数更正创建新 run；已生成的历史结果用于审计与对比，不允许激活旧工作流。检查点仅复用相同输入及版本的成功结果。

正式引擎只处理其支持的非金融行业；行业或必需输入缺失、期间/币种/口径冲突必须明确阻断。每股价值、企业价值到股权价值桥接和折现结果还经过确定性校验。规则检查不是独立金融专家审核。

## Agent 扩展

ToolSpec 定义名称、说明、参数类型和处理函数；ToolRegistry 校验工具白名单与参数。AgentToolProvider.tool_specs(session) 将工具加入同一个工作区循环。当前每轮最多 40 次模型调用，工具失败有独立的有界重试保护。

来源文本是不可信数据，不得成为执行指令。工具不能写入密钥或模型内部思考，也不能绕过输入冻结、证据校验及工作区审批策略。数值正式报告来自确定性结果，不由模型自由文本覆盖。

交付新金融实现时应同时提供：字段和单位字典、适用条件、类型化输入输出、版本标识、人工核对金样本以及异常边界测试。细化金融设计仍参考同目录的 v6.0 方案文档。
